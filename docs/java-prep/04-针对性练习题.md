# 针对性练习题

练习只围绕当前仓库出，不额外引入陌生业务。建议每天做 2 到 4 题，先口述，再写答案。

## 第 1 周练习

### 1. 对象模型

1. 为什么这个项目里要同时存在 `Entity`、`DTO`、`VO`，而不是只保留一个对象类型？
2. `BeanUtils.copyProperties` 适合解决什么问题？它有哪些局限？
3. 如果把数据库实体对象直接返回前端，可能会带来哪些问题？

### 2. 集合与泛型

1. `OrderServiceImpl` 里为什么大量使用 `List`，而不是数组？
2. `DishController` 清理缓存时为什么用 `Set` 接收 Redis keys？
3. `HashMap` 的 key 为什么需要满足稳定的 `hashCode` / `equals` 语义？
4. `Map` 作为 MyBatis 查询条件参数时有什么优点和缺点？

### 3. 异常

1. 为什么 `OrderBusinessException` 这类异常更适合设计成运行时异常？
2. `GlobalExceptionHandler` 统一处理异常，相比控制器里各自 `try-catch` 的优势是什么？

本周口述题：

- 用 3 分钟解释 `DTO`、`VO`、`Entity` 在这个项目中的职责。

## 第 2 周练习

### 1. 面向对象与分层

1. 为什么要保留 `OrderService` 接口和 `OrderServiceImpl` 实现类？
2. 如果把大部分业务逻辑直接写在 controller，会有哪些问题？

### 2. 注解、反射、AOP

1. `@AutoFill` 的作用是什么？
2. `AutoFillAspect` 是如何拿到方法注解和实体对象的？
3. 为什么自动填充适合放在切面而不是每个 service 方法里重复写？
4. 反射虽然灵活，但代价是什么？

### 3. ThreadLocal 与 Stream

1. `BaseContext` 为什么要基于 `ThreadLocal` 实现？
2. 为什么使用完 `ThreadLocal` 通常要清理？
3. `repetition()` 方法里用 Stream 把订单明细转换成购物车，有什么好处？
4. 什么情况下你会把 Stream 改写成普通循环？

本周口述题：

- 用 5 分钟解释“JWT 拦截器 + ThreadLocal + AOP 自动填充”是如何串起来的。

## 第 3 周练习

### 1. Spring 与事务

1. `DishServiceImpl.saveWithFlavor()` 为什么要加 `@Transactional`？
2. 如果插入菜品成功了，但插入口味时失败了，没有事务会发生什么？
3. Spring 事务在什么情况下可能失效？
4. 为什么事务通常放在 service 层，而不是 controller 或 mapper 层？

### 2. MyBatis 与分页

1. 为什么这个项目既有 Mapper 接口，也有 XML SQL？
2. `PageHelper.startPage(...)` 的思路是什么？它为什么能影响后面的查询？
3. 什么时候适合写动态 SQL，而不是把所有条件写死？

### 3. Redis 与缓存

1. 用户端菜品缓存的 key 为什么设计成 `dish_分类id`？
2. 管理端修改菜品后为什么要删缓存？
3. 手动删缓存方案的优点和不足分别是什么？
4. `@Cacheable` 和手动 `RedisTemplate` 操作各适合什么场景？

本周口述题：

- 用 5 到 8 分钟讲一次用户下单链路，重点突出事务和状态流转。

## 第 4 周练习

### 1. 并发与运行时

1. `WebSocketServer` 里使用普通 `HashMap` 保存会话，有什么潜在风险？
2. 为什么 `ThreadLocal` 在使用线程池时更需要小心？
3. 订单定时取消任务和请求线程并发修改同一订单时，可能带来什么问题？

### 2. JVM 入门

1. 一个 `Orders` 对象从创建到回收，大致会经历什么过程？
2. 为什么频繁创建短生命周期对象通常由 JVM 自动回收，但仍然要关注对象数量？
3. `String` 为什么设计成不可变类？

### 3. 项目表达

1. 这个项目最大的技术亮点是什么？
2. 如果让你说一个最能体现后端思维的模块，你会选哪个？为什么？
3. 如果给你一周继续优化这个项目，你会优先改什么？

本周口述题：

- 模拟 15 分钟项目面试，至少覆盖：项目架构、下单链路、AOP、事务、缓存、WebSocket、改进点。

## 参考答题要求

每道题都尽量按这个结构回答：

1. 先给定义
2. 再结合项目举例
3. 最后补一句可优化点或注意事项

## 自测红线

如果你出现下面任一情况，就说明这一块还没有真正掌握：

- 只能背概念，无法对应到仓库代码
- 只能说“用了什么”，说不出“为什么这么做”
- 一问到边界情况和缺点就卡住
