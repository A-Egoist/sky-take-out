# 复盘清单与模拟面试

这份文件用于每周末自查，也用于入职前最后一周快速过一遍。

## 1. 项目口述模板

你可以按下面顺序介绍项目：

1. 项目背景
   - 这是一个外卖平台后端，分为管理端和用户端。
2. 技术架构
   - 基于 Spring Boot、MyBatis、Redis，采用 Maven 多模块和典型分层结构。
3. 核心业务
   - 实现了员工管理、分类、菜品、套餐、购物车、地址簿、订单、报表、店铺状态等功能。
4. 重点技术
   - JWT + 拦截器鉴权
   - ThreadLocal 传递用户上下文
   - AOP 自动填充公共字段
   - 事务保证多表一致性
   - Redis 缓存提升查询性能
   - WebSocket 实现来单和催单提醒
   - 定时任务处理超时订单
5. 最大亮点
   - 下单链路完整，串联了业务校验、事务、外部接口、状态流转、实时通知和定时补偿。
6. 可优化点
   - 测试覆盖、缓存一致性、ThreadLocal 清理、WebSocket 并发安全、支付幂等。

## 2. 必会口述题

### 题目一：讲一下用户下单链路

至少覆盖这些点：

- 用户请求先经过用户端 JWT 拦截器
- 拦截器解析 token，把用户 id 放入 `ThreadLocal`
- service 层读取当前用户，校验地址簿和购物车
- 调用百度地图接口校验配送范围
- 事务中写订单表、订单明细表，并清空购物车
- 支付成功后修改订单状态
- 通过 WebSocket 向商家推送来单消息
- 后续通过定时任务处理超时未支付订单

### 题目二：讲一下公共字段自动填充

至少覆盖这些点：

- mapper 方法上标注 `@AutoFill`
- AOP 在方法执行前拦截
- 通过注解判断是插入还是更新
- 从 `ThreadLocal` 取当前用户 id
- 通过反射调用实体 setter 填充时间和用户字段
- 好处是减少重复代码，统一审计逻辑

### 题目三：讲一下项目里的缓存设计

至少覆盖这些点：

- 用户端菜品列表使用 Redis 缓存
- key 按分类维度设计，例如 `dish_100`
- 管理端修改菜品后主动删除相关缓存
- 套餐查询使用 Spring Cache 注解
- 这样做提升了热点查询性能，但仍要注意缓存一致性
