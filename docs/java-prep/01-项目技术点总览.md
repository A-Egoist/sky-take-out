# 项目技术点总览

这份总结按当前仓库真实实现来写，适合你做项目介绍、简历梳理和面试开场。

## 1. 项目架构

- 项目采用 Maven 多模块结构：
  - `sky-common`：常量、异常、上下文、工具类、统一返回、配置属性
  - `sky-pojo`：`Entity`、`DTO`、`VO`
  - `sky-server`：控制层、业务层、数据访问层、配置类、任务、WebSocket
- 整体是典型分层架构：
  - `controller` 负责接收请求和返回结果
  - `service` 负责业务编排
  - `mapper` 负责数据库交互
  - `resources/mapper/*.xml` 负责复杂 SQL

面试表达：
`我把项目拆成了公共模块、对象模块和服务模块，目的是把工具能力、数据模型和业务逻辑分开，降低耦合，也方便后续扩展。`

## 2. 基础框架与工程能力

- 使用 `Spring Boot 2.7.3` 作为整体开发框架
- 使用 `MyBatis` 完成 ORM 映射与 SQL 编写
- 使用 `PageHelper` 实现分页查询
- 使用 `Druid` 管理数据库连接池
- 使用 `Knife4j` 生成管理端和用户端接口文档
- 自定义 `JacksonObjectMapper` 统一 JSON 序列化行为

面试表达：
`这个项目不是单纯靠原生 JDBC 写的，而是基于 Spring Boot + MyBatis 做分层开发，兼顾开发效率和 SQL 可控性。`

## 3. 认证鉴权与上下文传递

- 管理端和用户端分别通过 JWT 拦截器鉴权：
  - `JwtTokenAdminInterceptor`
  - `JwtTokenUserInterceptor`
- 拦截器解析 token 后，将当前登录用户 id 写入 `BaseContext`
- `BaseContext` 基于 `ThreadLocal<Long>` 保存当前线程上下文
- 后续 `service`、`aspect`、`mapper` 可以读取当前用户 id，用于审计字段填充和业务处理

仓库落点：

- `sky-common/src/main/java/com/sky/context/BaseContext.java`
- `sky-server/src/main/java/com/sky/interceptor/*.java`
- `sky-server/src/main/java/com/sky/config/WebMvcConfiguration.java`

面试表达：
`我把登录态解析放在拦截器层，把用户 id 通过 ThreadLocal 向下传递，避免在每一层方法签名里重复透传用户信息。`

## 4. 横切能力与统一规范

- 自定义注解 `@AutoFill` 标记公共字段自动填充的方法
- 使用 `AutoFillAspect` 在插入和更新前统一填充：
  - `createTime`
  - `createUser`
  - `updateTime`
  - `updateUser`
- 通过反射调用实体的 setter，减少重复样板代码
- 使用 `GlobalExceptionHandler` 统一处理业务异常和 SQL 异常
- 使用 `Result`、`PageResult` 统一接口返回结构

仓库落点：

- `sky-server/src/main/java/com/sky/annotation/AutoFill.java`
- `sky-server/src/main/java/com/sky/aspect/AutoFillAspect.java`
- `sky-server/src/main/java/com/sky/handler/GlobalExceptionHandler.java`
- `sky-common/src/main/java/com/sky/result/*.java`

面试表达：
`我把重复的审计字段填充抽成了 AOP，避免每个 service 手写相同逻辑，同时通过全局异常处理器保证接口返回风格一致。`

## 5. 核心业务能力

### 菜品与套餐

- 菜品新增和修改涉及菜品表与口味表的多表操作
- 套餐新增和修改涉及套餐表与套餐菜品关系表的多表操作
- 使用 `@Transactional` 保证多表更新的一致性
- 删除和启停售前会做业务校验，例如：
  - 起售中的菜品不可删
  - 被套餐关联的菜品不可删
  - 启售套餐前要检查其中是否包含停售菜品

代表文件：

- `DishServiceImpl`
- `SetmealServiceImpl`

### 订单链路

- 用户下单流程包含：
  - 校验地址簿
  - 校验购物车
  - 调用百度地图 API 判断配送范围
  - 写入订单主表
  - 批量写入订单明细表
  - 清空购物车
- 支付成功后更新订单状态，并通过 WebSocket 向商家侧推送来单提醒
- 支持用户取消订单、商家取消订单、拒单、接单、派送、完成、催单、再来一单
- 使用定时任务处理超时未支付订单和超时派送订单

代表文件：

- `sky-server/src/main/java/com/sky/service/impl/OrderServiceImpl.java`
- `sky-server/src/main/java/com/sky/task/OrderTask.java`

面试表达：
`订单模块是这个项目最完整的一条业务链路，里面串联了参数校验、事务、多表写入、外部接口、状态流转、定时补偿和实时通知。`

## 6. 中间件与扩展能力

### Redis

- 用户端菜品列表使用 Redis 做缓存
- 管理端新增、修改、删除、启停售菜品时，手动清理相关缓存
- 套餐列表使用 Spring Cache 注解做缓存与失效控制
- 店铺营业状态也保存在 Redis 中

### WebSocket

- 使用 `@ServerEndpoint("/ws/{sid}")` 建立服务端推送通道
- 支持来单提醒和催单提醒两类消息

### 定时任务

- 定时取消超时未支付订单
- 定时处理长时间处于派送中的订单

### 报表与导出

- 基于订单和用户数据统计营业额、用户增长、订单完成率、销量 Top10
- 使用 Apache POI 基于模板导出近 30 天运营数据 Excel

### 第三方能力

- 微信小程序登录
- 微信支付预支付和退款预留接口
- 阿里云 OSS 文件上传
- 百度地图地址解析与配送距离校验

面试表达：
`除了基本业务，我还接入了 Redis、WebSocket、定时任务和第三方接口，让项目更接近真实后端场景。`

## 7. 这个项目最能体现你的地方

- 不是只做了 CRUD，而是实现了完整业务闭环
- 能把一个请求从鉴权、业务、数据库、中间件一直串到底
- 已经接触到事务、缓存、切面、定时任务、实时推送、外部接口
- 具备初步的工程拆分意识，而不是把所有逻辑堆进一个类

## 8. 面试里可以主动承认的改进点

- 当前测试更偏功能测试，单元测试和集成测试覆盖可以继续补
- `ThreadLocal` 使用后最好配合清理，避免线程复用带来的残留风险
- Redis 目前以手动删缓存为主，后续可继续优化缓存一致性策略
- WebSocket 会话容器目前使用普通 `HashMap`，在并发场景下可进一步加强线程安全
- 部分外部接口和支付逻辑还是偏教学实现，真实生产还要增加幂等、重试、超时和日志追踪
